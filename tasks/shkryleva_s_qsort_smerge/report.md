## 1. Введение
Параллельные вычисления играют ключевую роль в обработке больших объемов данных, позволяя значительно ускорить выполнение вычислительно сложных задач. В данной работе рассматривается задача сортировки массива целых чисел с использованием гибридного алгоритма, сочетающего быструю сортировку (QuickSort) на отдельных процессах и последующее слияние результатов. Реализация выполнена с использованием технологии MPI (Message Passing Interface) для распределения вычислений между несколькими процессами.

## 2. Постановка задачи
Разработать параллельный алгоритм сортировки массива целых чисел, использующий следующий подход:
1. Распределение массива между процессами
2. Локальная сортировка каждого блока с помощью алгоритма быстрой сортировки
3. Последовательное слияние отсортированных блоков в общий отсортированный массив
4. Обеспечение корректности работы при различных размерах входных данных и количестве процессов

## 3. Последовательный алгоритм
```cpp
bool sortArrayParts(std::vector<int> &data) {
  size_t dataSize = data.size();
  if (dataSize <= 1) {
    return true;
  }

  size_t midpoint = dataSize / 2;
  std::vector<int> leftSection(data.begin(), data.begin() + static_cast<ptrdiff_t>(midpoint));
  std::vector<int> rightSection(data.begin() + static_cast<ptrdiff_t>(midpoint), data.end());

  performQuickSort(leftSection, 0, static_cast<int>(leftSection.size()) - 1);
  performQuickSort(rightSection, 0, static_cast<int>(rightSection.size()) - 1);

  data = combineSortedArrays(leftSection, rightSection);
  return true;
}
```
Алгоритм использует рекурсивную быструю сортировку с последующим слиянием отсортированных половин, что обеспечивает временную сложность O(n log n) в среднем случае.

## 4. Схема распараллеливания
### Распределение данных
Блочное распределение с балансировкой: Исходный вектор делится на блоки между процессами, причем первые процессы получают на один элемент больше при наличии остатка от деления

Динамическое вычисление размеров:
```cpp
int baseChunkSize = dataSize / processCount;
int remainder = dataSize % processCount;
for (int proc = 0; proc < processCount; ++proc) {
  sendCounts[proc] = baseChunkSize + (proc < remainder ? 1 : 0);
}
```
### Коммуникационная схема
1. Broadcast размера данных (MPI_Bcast):
- Процесс 0 рассылает общий размер массива всем процессам
- Обеспечивает согласованность данных между всеми узлами

2. Распределение блоков (MPI_Scatterv):
- Процесс 0 распределяет данные с учетом неравных блоков
- Используются массивы sendcounts и displacements для точного указания размеров и смещений

3. Локальная сортировка:
- Каждый процесс сортирует свой блок с помощью рекурсивного QuickSort
- Временная сложность: O(k log k), где k = local_size

4. Последовательное слияние (централизованное):
- Процесс 0 собирает отсортированные блоки от всех процессов
- Выполняется поэтапное слияние полученных блоков в единый отсортированный массив
- Финальный результат рассылается всем процессам

### Анализ производительности:

Отрицательное масштабирование: Наблюдается четкая тенденция ухудшения производительности с увеличением количества процессов:
Ускорение снижается с 0.97 до 0.42
Эффективность падает с 48.5% до 5.3%

Причины отрицательного масштабирования:
Централизованный bottleneck: Процесс 0 выполняет последовательное слияние данных от всех процессов, что становится узким местом системы.
Коммуникационные издержки: На 8 процессах время коммуникации превосходит время вычислений:
Каждый процесс отправляет данные процессу 0
Процесс 0 выполняет 7 последовательных операций слияния
Результат рассылается всем 7 процессам
Неэффективная схема слияния: Текущий алгоритм имеет сложность O(kn), где k - количество процессов, n - общий размер данных.
Размер задачи недостаточен: Для 1,000,000 элементов при 8 процессах каждый процесс получает всего ~125,000 элементов, что слишком мало для компенсации коммуникационных затрат.

## Приложение
```cpp
bool ShkrylevaSQSortSMergeMPI::RunImpl() {
  int processRank = 0;
  int processCount = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &processRank);
  MPI_Comm_size(MPI_COMM_WORLD, &processCount);

  int totalDataSize = 0;
  if (processRank == 0) {
    totalDataSize = static_cast<int>(GetOutput().size());
  }

  MPI_Bcast(&totalDataSize, 1, MPI_INT, 0, MPI_COMM_WORLD);

  if (totalDataSize == 0) {
    MPI_Barrier(MPI_COMM_WORLD);
    return true;
  }

  std::vector<int> chunkSizes(processCount);
  std::vector<int> displacementOffsets(processCount);

  int baseChunkSize = totalDataSize / processCount;
  int remainder = totalDataSize % processCount;
  for (int proc = 0; proc < processCount; ++proc) {
    chunkSizes[proc] = baseChunkSize + (proc < remainder ? 1 : 0);
    displacementOffsets[proc] = (proc == 0) ? 0 : 
                                displacementOffsets[proc - 1] + chunkSizes[proc - 1];
  }

  std::vector<int> localChunk(chunkSizes[processRank]);

  if (processRank == 0) {
    MPI_Scatterv(GetOutput().data(), chunkSizes.data(), displacementOffsets.data(), 
                 MPI_INT, localChunk.data(), chunkSizes[processRank], MPI_INT, 
                 0, MPI_COMM_WORLD);
  } else {
    MPI_Scatterv(nullptr, chunkSizes.data(), displacementOffsets.data(), 
                 MPI_INT, localChunk.data(), chunkSizes[processRank], MPI_INT, 
                 0, MPI_COMM_WORLD);
  }

  if (!localChunk.empty()) {
    performParallelSort(localChunk, 0, static_cast<int>(localChunk.size()) - 1);
  }

  gatherAndMergeResults(GetOutput(), localChunk, processRank, processCount, chunkSizes);

  MPI_Barrier(MPI_COMM_WORLD);
  return true;
}
```
